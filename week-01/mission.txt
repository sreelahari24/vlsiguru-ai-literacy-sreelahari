Mission 2 — AI, ML, Deep Learning and Generative AI
1. Artificial Intelligence (AI)                                                                                                                     Artificial Intelligence is a field of computing that aims to build systems capable of performing tasks that normally require human-like intelligence, such as reasoning, recognising patterns, making decisions, and solving problems.
Example: A system that helps detect suspicious transactions in online banking.
2. Machine Learning (ML)
Machine Learning is a subset of AI in which computers learn patterns from data and use those patterns to make predictions or decisions instead of relying entirely on manually written rules.
Example: An email spam filter trained using examples of spam and legitimate messages.
3. Deep Learning (DL)
Deep Learning is a subset of machine learning that uses neural networks with multiple layers to learn complex patterns from large amounts of data.
Example: A deep neural network that recognises objects in photographs.
4. Generative AI (GenAI)
Generative AI refers to AI systems that generate new content, such as text, images, audio, video, or computer code, based on patterns learned from data.
Example: An AI assistant that generates a Python program from a natural-language description.

Mission 4 — Make AI Explain Itself, Then Test It
1. First Prompt
Prompt used:
"Explain how a Large Language Model (LLM) produces an answer to my prompt."
2. Beginner-Level Explanation
A Large Language Model is an AI system trained on large amounts of text and other data, depending on the model. During training, it learns statistical patterns and relationships between tokens, which are pieces of text such as words or parts of words.
When a user enters a prompt, the model processes the input as tokens and uses its learned parameters and computational layers to calculate likely next-token outputs. It generates a response by producing tokens step by step, using the prompt and the context available during generation.
The model does not simply search a database of complete answers every time. It generates text using patterns learned during training and the current context. Depending on the system, additional tools or retrieval mechanisms may also contribute information.
3. Second Prompt
Prompt used:
"Now explain how an LLM produces an answer to me as a beginner using a simple example."
4. Simple Example
Imagine asking an LLM: "The capital of India is..."
The model processes the text and uses its learned patterns and current context to generate a likely continuation, such as "New Delhi."
For a longer question, the model generates a sequence of tokens that forms a response. The result depends on the model, the prompt, the context, and the generation settings.
This example illustrates text generation; it does not mean that every response is guaranteed to be correct.

Mission 5 — Can AI Be Confidently Wrong?
1. Objective
The objective is to investigate whether an AI assistant can provide an incorrect or incomplete answer and to learn why independent verification is important.
2. Prompt
"Is 0.999... exactly equal to 1 in mathematics? Explain your answer and show a proof."
3. AI Answer to Investigate
The mathematically correct answer is yes. The repeating decimal 0.999... is exactly equal to 1, not merely approximately equal to 1.
A short proof is:
Let x = 0.999...
Then:
10x = 9.999...
Subtract the first equation from the second:
10x - x = 9.999... - 0.999...
9x = 9
Therefore:
x = 1
Since x represents 0.999..., we conclude that 0.999... = 1.
4. Independent Verification
Verification source: Khan Academy — repeating decimals and their relationship to fractions and real numbers.
https://www.khanacademy.org/math/arithmetic/arith-review-decimals
I would use the source to review repeating decimals and their mathematical representation, and compare that explanation with the algebraic proof above.
5. Verification Result
The answer is mathematically correct, as demonstrated by the algebraic proof. The proof is stronger evidence for this specific claim than simply accepting the AI's confidence.
The verification also has limits: checking one mathematical answer does not prove that every answer from the same AI system is correct.
6. Lesson Learned
AI can produce answers that sound convincing, but the quality of an answer must be judged using evidence and independent reasoning. For engineering work, I should verify important calculations, technical claims, and generated code before relying on them.

Mission 6 — Chatbot or Agent?
1. Important Concepts
Large Language Model (LLM)
An LLM is a model trained to process and generate language. It can answer questions, summarise documents, explain concepts, and generate code.
Example: A language model that explains a Verilog module.
AI Application
An AI application is a software product that uses one or more AI models to perform a task. It may also include a user interface, databases, business logic, and external tools.
Example: A learning application that uses an LLM to explain digital electronics.
Retrieval-Augmented Generation (RAG)
RAG is an approach in which an application retrieves relevant information from an external knowledge source and provides it to a generative model as context for answering a question.
Example: An assistant that searches a collection of semiconductor datasheets before answering a question about a component.
Tool-Using Assistant
A tool-using assistant can call external tools or software to obtain information or perform operations instead of relying only on text generation.
Example: An assistant that runs a Python calculation and explains the result.
AI Agent
An AI agent is a system that uses a model and available tools to work toward a goal through one or more steps. Depending on its design, it may observe results, decide what to do next, and continue until it reaches a stopping condition.
Example: An agent that searches technical documentation, compares relevant information, and prepares a report with citations.

Mission 7 — What Actually Runs AI?
1. What Is a CPU and What Is It Good At?
A Central Processing Unit (CPU) is a general-purpose processor that executes program instructions. It is designed to handle a wide range of tasks, including operating-system operations, program control, sequential logic, and general computation.
CPUs are useful for coordinating AI applications, running preprocessing tasks, managing memory, and executing AI inference workloads when appropriate.
2. What Is a GPU and Why Is It Useful for AI?
A Graphics Processing Unit (GPU) is a processor designed to execute many operations in parallel. GPUs contain many processing units that can perform large numbers of similar mathematical operations at the same time.
AI models often perform large matrix multiplications and tensor operations. These computations can be parallelised, making GPUs useful for training and running many AI models.
3. What Is an NPU or AI Accelerator?
A Neural Processing Unit (NPU) or AI accelerator is specialised hardware designed to execute common AI operations efficiently.
Depending on its architecture, it may support operations such as matrix multiplication, tensor processing, and neural-network inference. Specialised hardware can improve performance per watt and reduce latency for supported workloads.
Examples include NPUs in mobile devices and AI accelerators in data centres.
4. What Is Parallel Computation?
Parallel computation means performing multiple computational operations simultaneously instead of executing every operation one after another.
For example, a large matrix multiplication contains many calculations that can be distributed across multiple processing units. Parallel computation can reduce execution time when the workload and hardware support it.
However, not every task can be parallelised equally well, and communication and memory-access costs can limit performance.
5. Why Does AI Depend on Compute and Memory?
AI models require computation to perform mathematical operations and memory to store model parameters, input data, intermediate results, and outputs.
Large models may contain billions of parameters. Moving these parameters between memory and processing units can consume substantial time and energy.
Consequently, AI performance depends not only on the processor's computational capability but also on memory capacity, bandwidth, data movement, and software efficiency.
6. Difference Between Training and Inference
Training is the process of adjusting a model's parameters using data and an optimisation procedure. It commonly involves forward computation, calculating a loss, backpropagation, and parameter updates.
Inference is the process of using an already-trained model to produce predictions or outputs for new inputs. Inference generally does not update the model's parameters.
Training often requires substantial compute and memory resources, particularly for large models. Inference requirements depend on the model, input size, batch size, latency target, and hardware.

8. Real AI Workload Example
Workload: Image Classification
Consider an image-classification system that identifies objects in a photograph.
The application sends an image to a trained neural network. The software framework prepares the image and executes the model's operations on available hardware. The model performs numerical calculations using its learned parameters and generates class scores.
A GPU can be useful when processing many images because convolution and matrix operations can be parallelised. A specialised AI accelerator may be suitable for efficient inference on supported operations. A CPU may also be sufficient for smaller models or low-throughput applications.
The appropriate hardware depends on the model size, performance requirements, memory capacity, power consumption, cost, and available software support.
Conclusion
AI software relies on computing hardware to execute the mathematical operations required by a model. CPUs provide general-purpose computation, GPUs support highly parallel workloads, and AI accelerators specialise in selected neural-network operations. Understanding compute, memory, training, and inference helps engineers evaluate the hardware requirements of AI applications.
Mission 8 — Where Could AI Help My VLSI Track?
1. Selected Track: Physical Design (PD)
Physical Design (PD) is a stage in the VLSI design flow where a synthesized circuit is transformed into a physical layout. It involves floorplanning, placement, clock tree synthesis, routing, and timing and physical verification.
2. Task Where AI Could Help
One task where AI could help in Physical Design is Power, Performance, and Area (PPA) optimization.
During physical design, engineers must explore different implementation options to meet timing, area, and power constraints. This process can require multiple iterations of placement, routing, and timing analysis.
AI and machine-learning techniques can help explore different design configurations, predict implementation outcomes, identify promising optimization options, and reduce the time spent on repetitive experiments.
3. AI Application Table

Benefits of Using AI in Physical Design
AI could help engineers analyse large amounts of implementation data, identify patterns in timing and congestion reports, and explore multiple design configurations more efficiently.
For example, an AI-assisted optimization system could evaluate different implementation settings and help identify configurations that may improve timing without exceeding area constraints.
AI could also assist in summarising timing reports, generating analysis scripts, and identifying potential causes of design failures.
5. Why Human Engineering Knowledge Still Matters
AI-generated recommendations are not guaranteed to produce a better physical design. A configuration that improves timing may increase area or power, and a predicted improvement may not appear in the actual implementation.
Physical Design engineers must understand floorplanning, placement, clock tree synthesis, routing, static timing analysis, design rules, and PPA trade-offs.
They must validate recommendations using the EDA tools, inspect implementation reports, and confirm that the final design satisfies all required constraints.
Conclusion
AI can support Physical Design by assisting PPA optimization, placement exploration, timing analysis, and congestion prediction. It can reduce repetitive work and help engineers explore design options more efficiently. However, actual implementation results must be verified using physical design and timing analysis tools. AI supports the optimization process, while engineers remain responsible for technical decisions and final design quality.

Mission 9 — My AI Working Agreement
Objective
To establish five rules for using AI responsibly and effectively while learning engineering concepts and solving technical problems.
Rule 1: Verify Important Technical Information
I will independently verify important AI-generated technical claims using reliable sources, official documentation, mathematical reasoning, simulations, or experiments.
For example, when AI explains a digital circuit or suggests a DFT testing approach, I will check the explanation against appropriate technical references and test results.
Rule 2: Never Share Confidential or Proprietary Information
I will not enter confidential company information, restricted design files, proprietary RTL, passwords, private keys, or other sensitive information into an AI tool unless its use is explicitly authorised under the applicable policies.
I will use public examples or appropriately sanitised data when learning or experimenting.
Rule 3: Take Responsibility for My Final Work
I will ensure that I understand the final answers, diagrams, programs, and technical decisions I submit. I will not treat AI-generated output as automatically correct or submit work that I cannot explain.
AI can assist my learning, but I remain responsible for the quality, correctness, and integrity of my work.
Rule 4: Test AI-Generated Code and Engineering Solutions
When AI generates code, scripts, circuit logic, or technical procedures, I will review and test them before relying on the results.
For example, I will compile or simulate Verilog code where appropriate, check expected outputs, and investigate any mismatches instead of assuming that generated code is correct.
Rule 5: Use AI to Improve Understanding, Not Just to Obtain Answers
I will ask AI for explanations, examples, alternative approaches, and feedback on my understanding. I will try to solve problems myself and use AI to identify gaps in my knowledge.
I will also compare important claims with independent evidence and record what I learned from any errors or corrections.
Justification for My Rules
Missions 4 and 5 emphasise that AI explanations should be checked against reliable evidence. Even when an explanation sounds convincing, it is important to distinguish a plausible response from a verified result.
This is why verification is central to my working agreement. In engineering, an incorrect technical conclusion can affect design quality, testing, reliability, and debugging. Independent checks and experiments help me decide when an AI-generated result can be trusted.
Conclusion
My working agreement is to use AI responsibly, verify important claims, protect confidential information, test generated solutions, and take ownership of my final work. These rules will help me become an engineer who can use AI effectively without depending on it blindly.
